# DSH Sidecar 归档与可写插件目录

状态：已完成。遵循 [官方归档与用户安装目录规范](../spec/dsh-compat-mapping.md#官方归档与用户安装目录)。

1. 将新安装的插件放到 profile 的真实目录，保留旧布局的读取兼容。验证用户插件安装后可加载、卸载后不可用。更新桌面和 headless 的 Sidecar 解析。
2. 构建 Windows `rc.5` 的只读 VFS。原生模块及独立进程的依赖随包落盘，校验归档和原生目录中的锁定包文件。更新打包、暂存和门禁脚本。
3. 执行现有 Windows 官方门禁、打包自检、workspace 严格 Clippy、文档链接检查和代码质量门禁。记录新旧布局的文件数。

验收命令见 [Windows 打包指南](../m4-package.md) 与 [代码质量门禁](code-quality.md#本地与-ci-验收)。

## 本机测量

- Windows x64 `rc.5` 调试包使用同一 npm 锁。旧包解压后有 9,785 个 Sidecar 文件，新包有 3,889 个。`official.zip` 内有 5,883 个条目，53 个需要真实路径的依赖包装在外层发行 ZIP 内。
- 空插件清单下测了 5 次 Node 启动、Sidecar 握手和进程退出。使用同一 Node `26.13.1`，归档布局中位数为 0.240 秒，旧目录布局为 0.122 秒。原生依赖随包落盘，启动路径不执行原生依赖解包。

Windows x64 调试包通过发行自检和 28 项官方 `rc.5` 兼容测试。workspace 严格 Clippy、代码质量门禁和文档链接检查通过。
