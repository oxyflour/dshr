# ADR-0005 — 不做"Web 壳 + 现有 Web Client"的捷径

- 状态：**Accepted**
- 日期：2026-11-08
- 关联：PLAN ADR-009 / §1.3 / ADR-006

## 背景

最省力的产品化路径是：拿 Tauri 或 Electron 包一层现有 DSH Web Client，10–25 日就能得到一个"桌面应用"。评审要求把这条路径的取舍留在文档里，避免"因为能写所以要做"。

## 选项与代价

| 路径 | 估算 | 得到什么 | 失去什么 |
|---|---|---|---|
| **A. Tauri/Electron 包 Web Client** | 10–25 日 | 立刻有桌面外壳 | 原生多面板、原生终端、GPU 虚拟化；插件生态仍是浏览器 Cordis，长期被上游节奏绑定 |
| **B. 只写 DSH Client 插件** | 5–15 日 | 最低成本进入 DSH 生态 | 受宿主能力上限约束；无法定义自己的 Tool/Session/Policy 语义 |
| **C. Rust Agent Core + 现有 Web UI（Tauri）** | 60–100 日 | 自有 Agent 语义 + 较快 UI | 永久放弃原生交互与性能优势 |
| **D. GPUI 原生桌面（本计划）** | 240–390 日 | 原生交互 + 可长期演进的插件平台 + 自有 Agent 语义 | 最贵；且依赖 GPUI 生态的成熟度 |

## 决定

选择 **D**，理由是差异必须同时落在三点上：**原生交互**、**可长期演进的插件平台**、**自有 Agent 语义**。任何两点不成立，D 就不划算，应回到 C。

同时保留 C 作为明确退路：M1 的 GPUI 判死实验（10k 事件虚拟化、中文 IME、WebView2 叠层）若不通过，立即转向 C，而不是继续加码 D。

## 后果

- **好消息**：架构不与浏览器绑定；UI 扩展契约（ADC-v1）与 Renderer 解耦，未来换 Renderer 不需要重写插件。
- **坏消息**：M2 之前看不到"像样的界面"；UI 核心（对话/终端/Diff/虚拟化）是 GPUI 生态里最贵的一块，估算已按 1.7–1.8× 修正。
- 机会成本：同样 30 日的投入，A 已经能交付可用产品；D 只能交付三个判死结论。

## 反悔条件

1. 判死实验 A 不通过（性能或中文 IME 硬伤）→ 转 C。
2. 上游 DSH 桌面端在 12 个月内覆盖本项目 80% 的目标场景 → 重新评估是否值得做 D。
3. GPUI 上游出现长期不可用的 Windows 缺陷 → 转 C，并保留 Agent Core。

## 验证

- M1 结束时，三个判死实验有明确结论（通过 / 不通过 / 部分通过）。
- 若转 C，Agent Core、Session Log、Sidecar RPC、ADC-v1 的服务端部分必须可复用（这是本决定的隐性验收条件）。
