# ADR-0009 — 最小插件信任链：包级信任文件 + 摘要强制 + 可选 ed25519

- 状态：Accepted
- 日期：2026-11-14
- 关联：[`../PLAN.md`](../PLAN.md) §8 M3、[`../spec/plugin-trust.md`](../spec/plugin-trust.md)、
  [`0007-m3-scope.md`](0007-m3-scope.md) §1 第 8 项、[`004`](0004-adc-slot-contract.md)

> **M4 更新（2026-11-16）**：第 6 条的"密钥吊销/轮换"已作为 W1 交付（[ADR-0013](0013-m4-scope.md)，
> spec §4，`M4-KEY-001..010`）；CA/证书链、时间戳/透明日志、远程 registry 信任根仍未做。

## 背景

M3 要求"最小信任链：签名（或来源校验）+ 首次安装风险提示；不要求完整证书体系"
（PLAN §8 M3）。当前 `profile::install` 只做路径安全与离线复制，不校验摘要、不检查来源、
无首装确认、无降级拒绝、无审计。M2 的安装只有 CLI 显式调用 + 简单审计日志。

威胁模型（[`spec/plugin-trust.md`](../spec/plugin-trust.md) §1）：攻击者能改写安装介质，
不能改写宿主信任密钥库。因此需要"防篡改 + 来源可选验证 + 用户知情"，不是完整供应链安全。

## 选项

| 选项 | 内容 | 结论 |
|---|---|---|
| A. 完整签名体系（CA/吊销/时间戳） | 需网络、证书链、吊销分发 | 否决：M4 范围，M3 无法闭环 |
| B. 只做 sha256 摘要，不做签名 | 实现最小，但无法区分"发布方签名"与"任意人重算摘要" | 否决：摘要只能防介质篡改，防不了替换包 |
| **C. 包级 `dshr-trust.json` + 摘要强制 + 可选 ed25519 + 首装确认 + 审计 + 降级拒绝** | 签名可选、密钥本地、无 CA；不做吊销/轮换 | **采用** |

## 决定

1. **信任文件是包级兄弟文件** `dshr-trust.json`，不放进 `plugin.toml` / `package.json`：
   manifest 无法包含自身摘要（自引用），也不能既是被签内容又是签名容器。
   这细化了 ADR-0007 §1 第 8 项"manifest `integrity`/`signature`"的表述——实际落点是包级信任文件；
   manifest 只保留 `min_host_version` 参与降级/兼容判定。
2. **摘要强制（声明即校验）**：`dshr-trust/v1` 的 `package.digest_sha256` 按
   spec §3 的规范化算法计算；不匹配立即拒绝（`E_INTEGRITY_MISMATCH`）。无信任文件的包允许安装，
   但必须首装确认并记为 `unsigned`（兼容 M3 已有 DSH JS 包与本地开发包）。
3. **签名可选（ed25519）**：签名输入为 `dshr-trust/v1\n<plugin_id>\n<version>\n<digest>`；
   公钥来自**本地** `<profile>/trust-keys.json`。有签名但密钥缺失/无效即拒绝；
   签名有效则免首装确认（仍写审计）。
4. **首装确认 + 降级拒绝 + 审计**：未验证签名（无信任文件/无签名）的包在首次安装必须经调用方
   注入的确认回调；已验证签名的包免确认（仍写审计）；已安装版本更高时拒绝降级（除非显式
   `--allow-downgrade`）；接受与拒绝都写 `<profile>/install-audit.jsonl`；安装后写
   `<dest>/.dshr-install.json`。
5. **实现依赖**：SHA-256 与 ed25519 都用工作区已锁定的 `ring = 0.17.14`（已编译，离线可用），
   不引入新外部 crate。
6. **不做**：CA/证书链、密钥吊销/轮换、时间戳/透明日志、远程 registry 信任根（均 M4）。

## 后果

**好消息**：篡改包与降级包被拒；安装有可审计记录；签名可选的实现成本低（1 个模块 + ring），
G2 的"篡改/降级被拒"有可机检证据；不改变 M2 的安装路径（`install_package` 保留，新增可信入口）。

**坏消息**：无信任文件的包默认"未验证"，用户需要确认——对本地开发包是额外摩擦；
签名不做吊销，密钥泄露只能靠用户手动换钥；DSH JS 包没有权限模型，风险提示只能给通用文案。

## 反悔条件

- 若 M4 引入证书/registry 信任根，本 ADR 的"本地密钥库"扩展为证书链，`dshr-trust/v1` 升 v2；
- 若安装确认被证明干扰内部开发，可对"本地路径 + 无来源"包加 `--trust-local-dev` 豁免（需审计）；
- 若 ring 在目标平台不可用/编译失败，退化为 sha2（摘要强制）并显式标注"签名未验证"，不得静默接受。

## 验证

- `cargo test -p dshr-profile` 的 `CPP-TRUST-001..`（摘要确定性/篡改/有效签名/坏签名/未知密钥/
  首装确认拒绝/降级拒绝/审计/安装元数据）；
- `node schema/check.mjs` 的 `dshr-trust` fixture（正反例）；
- 手工：篡改包内容 → 安装失败且审计 `action:"reject"`；同包重装成功；改小版本号 → `E_TRUST_DOWNGRADE`。
