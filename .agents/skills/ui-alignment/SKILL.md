# 界面对齐

## 确认参考与范围

- 确定参考版本、目标入口、用户点名的模块和排除项。继续上一阶段时沿用已确认的范围和优先级。用户要求先列计划或差异清单时，交付清单供复核后等待实施授权。明确批准的阶段直接执行。
- 优先读取可用的参考源码、组件和样式。用构建产物、设计稿和运行截图补充源码无法确定的状态。优先使用项目已有的构建、测试和截图入口，界面自动化留给需要观察或操作真实窗口的步骤。
- 记录参考版本和证据位置。拆分组件、设计 token、状态和数据流，并对应到目标的实现入口。解析 CSS 变量、主题覆盖和布局约束。用截图测量时匹配窗口内容区尺寸、DPI、缩放、主题和交互状态，区分逻辑像素与截图像素。
- 有设计授权时按参考验证视觉细节。参考其他专有产品时，采用其布局和交互原则，保留目标应用自己的视觉身份、资源和内容。
- 对齐 DSH Desktop 与本仓库的 GPUI 桌面端时，读 [DSHR 对照与验证](references/dsh-gpui.md)。

## 差异排序与实施

每条差异给出优先级、模块和复现状态、当前表现、参考证据、建议改动及可观察的验收条件。用 `P1` 标记阻断主要流程、导致错误结果或显著影响主要操作的问题，用 `P2` 标记明显且有明确修复范围的布局与交互差异，用 `P3` 标记次要状态和细节。优先处理会影响多个组件的根因，并标明前置依赖。

- 优先改目标应用共用的 token、组件和锚定逻辑。区分默认态与悬停、聚焦、禁用、加载和错误态。涉及覆盖层时，检查触发器对齐、边界收缩、层级、遮挡、键盘退出和焦点恢复。
- 界面操作接入当前应用的状态、权限与持久化。按已授权范围复用现有能力。账号、反馈和数据发送等操作需要明确的业务范围及实际去向。遇到缺失的后端能力时，记录具体差异和依赖。
- 保持本阶段之外的接口和构建入口兼容。已有本地工作通过限定文件或补丁范围来保留。涉及公开契约或跨模块变更时，按目标仓库约定更新规范和验收记录。

## 验证与交付

- 从正常入口运行目标应用，通过复现场景检查视觉和交互。按改动选择窄窗、深色、默认与悬停、初始与会话中等状态。原生应用优先用窗口自身的截图或诊断接口。
- 需要保存、切换或触发业务行为时，核对界面显示、落盘结果及实际效果。用独立数据目录和测试数据执行验证。运行现有的相关测试，并确认发布产物与验证使用的构建一致。
- 交付已修复项、验收结果和仍有差异的状态。分别说明从源码确认的依据与已经在运行窗口复核的行为。附有助复核的代码位置、截图或产物路径。
