# ADR-0004 — ADC-v1 采用 slot 注册表，而不是组件类型清单

- 状态：**Accepted**
- 日期：2026-11-08
- 关联：PLAN ADR-010 / §4.1 / [`../spec/adc-v1.md`](../spec/adc-v1.md)

## 背景

v0.1 把 Client 扩展定义为六种 Contribution：`panel` / `tool_renderer` / `widget` / `command·menu` / `viewer` / `settings`。

对照本机 DSH 实现：Client 侧有 **135 个 slot 节点**、四种 kind（`single` / `list` / `keyed` / `chain`）、三种 scope（`root` / `session` / `session-maybe`），每槽带注册契约与替换风险标注。也就是说，真实挂载点的粒度远细于六种组件。

## 选项

| 选项 | 后果 |
|---|---|
| **A. 六种组件清单** | 简单；但第三方只能挂在六个位置，表达力弱于 DSH；DSH 插件移植 = 重写 |
| **B. slot 注册表 + 预置分组** | 复杂一点；挂载点细、可增量扩展；六种组件退化为文档分组 |
| **C. 直接暴露 React 式组件树** | 表达力最强；但把 Renderer 实现（GPUI）耦合进公开契约，违背 ADR-003 |
| **D. 只做 WebView** | 简单；但放弃原生体验，违背 ADR-006 |

## 决定

采用 **B**：

1. 宿主声明 slot（`kind` / `scope` / 注册契约 / 替换风险），插件只能注册到已声明 slot。
2. 插件提交**声明式元素树**（JSON），元素集在 [`adc-v1.md`](../spec/adc-v1.md) §6 冻结范围内。
3. 六种 Contribution 保留为**文档分组与权限归类**，不再是运行时原子。
4. 工具卡内的任意渲染明确不做（见 spec §D），只给预置渲染器与受限附加区。

## 后果

- **好消息**：一个按钮、一行设置、一个工具结果渲染器都有非破坏性的落点；DSH 插件移植从"重写"降为"改挂载点 + 重写视图层"；元素树可在 GPUI 与 WebView 两条路线复用。
- **坏消息**：必须自己设计并冻结元素词汇表（2–3 周设计 + 实现），这部分在 v0.1 完全没有估算；slot 越多，宿主维护成本越高。

## 反悔条件

- 若 M3 冻结后发现 80% 的插件只需要 < 8 个 slot → 可收敛目录（保留机制）。
- 若元素词汇表无法覆盖真实需求（例如必须自由绘制）→ 该场景改走独立 WebView Panel，而不是扩张元素集。

## 验证

- `ADC-SLOT-*` conformance 全绿：注册、撤销、冲突、key 域校验、generation 失效。
- 用两个真实插件（一个 CAD 面板、一个设置项）验证"不读主程序源码即可接入"。
- 统计：第三方插件平均需要的 slot 数（目标 ≤ 3）。
